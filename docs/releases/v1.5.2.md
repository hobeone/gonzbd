## Fixes

**A job resumed after a restart no longer finishes a file short.** (#1066)
On restart, gonzbd reads back the bytes each unfinished job already wrote and marks the articles they cover as done.
The job became visible to the downloader one step before those marks were installed,
so a download pass that landed in between fetched those articles again.
The copies were refused against the bytes already on disk, but each refusal still counted toward the file's parts,
so the file was declared finished with its last articles never fetched and was truncated to the bytes written so far.
The re-fetched articles were also recorded as permanently failed.
The window was short, so the exposed case was a restart with more than one active job,
where another job's progress triggered a download pass at that moment.
A post with par2 could repair the damage; a post without par2 completed truncated.
The job is now made visible and its read-back installed in one step.
The bug was present since 1.5.0.
