## Upgrading from 1.5.2

No database schema, manifest format or configuration key changed.
An existing data directory from 1.5.2 works as it is.

## Fixes

**A RAR set that does not start at its first volume now fails instead of reading as empty.** (#1072)
A middle volume named like volume 1 (`obf.part1.rar`) read as a clean, empty archive.
DirectUnpack recorded it as a successful set with no files,
and the unpack stage counted it among the successful archives and queued its volume for deletion at finalize.
The set is now a failure that says it is missing its first volume, and its volumes stay in place.
It is not retried with `unrar` even under `go_rar_fallback`:
given the same volumes, `unrar` extracts at most the members that start later and reports the failure under its own exit-code label.
The `go_rar_fallback` description in the UI says so.
Listing the members of a volume taken from anywhere in its set still reports the members that start in it.

**The title in the navigation bar opens the main view.**
It opened the GitHub repository in a new tab, which left no way back to the main view from the status page.

## About this release

rarengine is updated from v1.5.0 to v1.6.1 and par2engine from v1.1.4 to v1.1.5.
par2engine v1.1.5 panics at start-up on a big-endian CPU, where its little-endian kernels would otherwise compute wrong results silently.
The other changes are dependency updates: Go 1.27.4, goose 3.30.1, modernc.org/sqlite 1.62.0,
playwright-go 0.6401.0, brotli 1.3.0, and the UI and tooling dependencies.
