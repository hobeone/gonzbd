## Upgrading from 1.2.x

Read this before you start v1.3.0 against an existing installation.

1. **Use a fresh data directory.**
   The database schema (`001_initial.sql`) was edited in place and gonzbd does not migrate it.
   A database written by 1.2.x carries the same migration version as this build, so it is not recognised as old and will not match the new schema.
   Move the old data directory aside before you start.
   History, queue state and failed-job retry state do not carry over, so re-add anything still queued.
2. **Config keys removed.**
   `downloads.write_cache_size` and `downloads.pre_check` no longer exist.
   If they are still in `gonzbd.yaml` they are ignored, with a `config: unknown field ignored` warning at startup, so you can delete them.
3. **Flat-layout categories are no longer supported.**
   A category whose `dir` ends in `*` (every job delivered into one shared directory) is refused when the config loads.
   Give the category its own subdirectory.
4. **Archives are deleted only at post-processing level 3.**
   Level 2 (repair and unpack) now keeps the source archives, as the level names say.
   The default category is level 3, so a default setup behaves as before.
   `enable_rar_cleanup` still has to be on for level 3 to delete them.
5. **Behind a reverse proxy, review the forwarded-header settings.**
   Forwarded-header handling now fails closed.
   Set `local_ranges` to the proxy's address, `verify_xff_header: true`, and `trusted_forward_header` to the header your proxy manages.
   Without that, cookie-based web UI login can be refused for forwarded requests; API-key and NZB-key authentication are unaffected.
   `gonzbd.yaml.example` explains each case.
6. **Two queue fields were renamed.**
   In `mode=queue`, `par2_bytes` and `par2_files` are now `recovery_bytes` and `recovery_files`, and they count recovery volumes only, not the par2 index.
   These are gonzbd extensions with no SABnzbd counterpart; the SABnzbd-compatible fields are unchanged.

## Highlights

**Crash and restart durability** was rebuilt on a record of each written article.
A restart verifies what is on disk against that record, paused jobs are verified after startup instead of before the API listens, overlapping durable articles are detected and reported, and corrupt job and index files are quarantined on load instead of blocking startup.

**Post-processing**
- A native Go tar extractor (`enable_tar`), RAR3/RAR4 decoding, and recovery of fully obfuscated RAR volume sets from their RAR5 headers.
- RAR5 members are decoded in parallel by default, and `unrar` is skipped for passwords that can be shown wrong beforehand.
- Unwanted extensions are checked at ingest and after unpack, and archives are inspected for them while still downloading.
- Archive extraction subprocesses can be sandboxed at the OS level (`strict_sandbox`, rejected at startup on platforms that cannot enforce it).
- par2 repairs fetch only the recovery volumes they need, can use a recovery volume as the index when none is on disk, and have configurable packet and junk-scan limits.
- Scripts receive `SAB_FILES`, and `redact_script_secrets` is available for scripts that should not see secrets.

**Downloader and NNTP**
- Server priority is strict instead of overflowing to lower-priority servers.
- A connection fault in the middle of a fetch is charged to its connection, not the server, and dead pooled connections are discarded without a server penalty.
- Decoded-but-unwritten article bytes are bounded.
- Duplicate Message-IDs in an NZB are dropped and Message-IDs are validated when the NZB is parsed.
- Pipelining depth is reported per connection.

**API and UI**
- A `mode=health` endpoint, an extended status page (general info, news servers, system info), and build time and commit in the UI.
- The add-NZB dialog can set priority and add paused.
- The queue and its listing are ordered on priority and served from resident state without loading jobs from disk.

**Docker, filesystems and performance**
- The image has a `HEALTHCHECK`, and multi-arch images are cross-compiled rather than emulated.
- NFS deletion handles silly-rename files, and a file-handle leak was fixed.
- Lower lock contention in the websocket broadcaster, allocation-free progress accessors, a lazily built article index, and pooled copy buffers.

## Fixes

This release carries 451 fixes, most of them in the app, queue, post-processing, dispatch, API, assembler and downloader packages.
The most recent ones change behaviour you may notice:

- A post that par2 could repair is no longer failed early by the failure-rate rule; that rule now defers to whether the damage fits the recovery data.
- A par2 set that cannot be read is repaired where possible, and otherwise delivered unverified instead of being reported clean.
- Cancelling a repair or an unpack no longer starts the external `par2`, `unrar` or `7z` fallback.
- NZBs inside a zip are named after the NZB, not the zip.
- Scripts now receive real values for `SAB_BYTES_DOWNLOADED`, `SAB_DOWNLOAD_TIME` and `SAB_AVG_BPS`, and `SAB_REPAIR` and `SAB_UNPACK` follow the job's post-processing level.
- A job with no par2 that loses content articles still fails, as before: a file is never delivered as complete when it is not.
