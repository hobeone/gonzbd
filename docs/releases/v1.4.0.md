## Upgrading from 1.3.x

**Use a fresh data directory.**
The database schema (`001_initial.sql`) and the per-job manifest format were edited in place and gonzbd does not migrate either.
`job_files` now carries each file's subject, size and article count, `dispatch_jobs.unwanted_ext` accepts a fourth value, and the manifest file is a flat article array.
A database written by 1.3.x carries the same migration version as this build, so it is not recognised as old and will not match the new schema.
Move the old data directory aside before you start.
History and queue state do not carry over, so re-add anything still queued.

No configuration key changed.

## Highlights

**Every queued job shows its progress after a restart.**
Before this release a job that was not downloading at shutdown came back with an empty file list and "Repair data unknown" until it ran again.
Now one pass over the download record, before the first tick, gives every job its file list and an estimated percentage.
The estimate is marked in the UI as progress from the download record, and it is checked against the files on disk the first time the job is loaded: on its first tick for a job that was running, on resume for a job that was paused.
The queue API reports this as a new `progress_verified` field on each slot and a `verified` flag on each file.
Both are gonzbd extensions; the SABnzbd-compatible fields are unchanged.

**Startup no longer verifies paused jobs.**
A job paused before the shutdown is restored paused with its estimate, and nothing reads its files until you resume it.
Startup is correspondingly faster on a queue with many paused jobs.

**The per-file structure left the manifest.**
Subject, size and article count live in `job_files` and stay resident for every registered job, so the file list of an evicted job is available without reading its manifest.

## Fixes

- A job blocked for an unwanted extension under the `fail` action could escape its failure.
  A storage fault during its startup load paused it, and resuming the paused job approved the block instead of failing the job.
  The owed failure is now persisted as its own state and survives any pause, resume or restart; resuming such a job no longer approves it.
- A job whose file structure cannot be restored from the database is reported as failed with the reason in its operational error, and no longer shows the "checked when the job next runs" hint beside that error.
- A startup test that raced the stall path under full-suite load was fixed.
