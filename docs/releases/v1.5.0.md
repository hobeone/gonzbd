## Upgrading from 1.4.x

No database schema, manifest format or configuration key changed.
An existing data directory from 1.4.x works as it is.

One API change: `mode=about` now requires the admin API key.
A client that read it with the upload-only NZB key gets `403`.

## Highlights

**A retry no longer inherits the earlier attempt's late articles.**
A retry registers under the ID of the attempt it replaces, and the assembler identified a write by that ID.
An article of the earlier attempt that was still in flight when the retry registered could land in the retry's file, mark the retry's article as done, record a row under the retry, or stall and fail the retry on a storage fault.
Writes and every report the assembler makes now name the job instance that produced them.
A report for an attempt that has left the queue is dropped or refused; the retry sees only its own work.

**Assembler memory no longer grows for the life of the process.**
Every file handed to post-processing left a per-file marker behind, and every cancelled or finished job left a job-level one.
Both are gone: the per-file markers are dropped with their job, and the job-level one is replaced by a check of the state the dispatcher already holds.

**History reads skip the script log.**
Every history read selected each entry's post-processing script output, up to 512 KiB per row, and no reader used it.
Reading 50 entries with large logs took 24.8 ms and 52.5 MB; it now takes 0.19 ms and 88 KB.

## Fixes

- `mode=about` called the public IP lookup services on every request, returned their bodies unchecked, and was readable with the upload-only key.
  The lookups are cached, the response is validated as an IP address, and the mode requires the admin key.
- A late article arriving while a job was being handed to post-processing could re-register the job's file and leak its cache entry.
  The hand-over now refuses such an article at the resolver.
